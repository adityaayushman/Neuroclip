# NeuroClip ML

Skill scoring and rupture-risk warning for the simulator. Everything is trained on **synthetic runs** produced by
scripted agents driving the real simulation headlessly, so the models describe the agents' behaviour, not real surgeons.
Educational use only.

## Pipeline

1. `node ml/datagen/run_all.mjs 20000` (repo root) simulates 20k runs by 40 virtual users of different skill and speed,
   sampling labelled 48 s windows (31 features at 1 Hz, built by the same TypeScript code the browser uses).
2. `python -m neuroclip_ml.run_all --data data --out artifacts` (in `ml/`) runs leave-one-user-out CV for a gradient-boosting
   baseline and leave-users-out CV for the neural models, fits Platt calibration, trains the final models, exports int8 ONNX,
   writes model cards and updates the table below. The ONNX files and `model_meta.json` are copied to `apps/web/public/models`.

Models: `SkillNet` (1D-CNN + GRU, expert-likeness) and `RiskNet` (LSTM, rupture within the horizon).
Model cards: `artifacts/MODEL_CARD_skill.md`, `artifacts/MODEL_CARD_rupture.md`.

## In the browser

- Both models run in a Web Worker (onnxruntime-web, single-thread wasm) on a rolling 48 s window at 10 Hz. The int8 files load as-is
  (`ConvInteger`, `MatMulInteger`, `DynamicQuantizeLSTM`); a `*-safe` variant is kept as a fallback.
- Measured on the dev machine: worker-reported inference for both models together was about 2.6 ms with the page visible;
  100 back-to-back calls from a hidden page (including the `postMessage` round trip) had a median of 5.2 ms and p95 of 9.4 ms,
  which is roughly 2.6 ms per model. Python/ORT CPU, one thread: 0.98 ms (skill) and 0.21 ms (rupture) per window.
- The browser logits for a known window match the Python int8 export to within about 0.02 (quantisation noise).

## Honest limits

- Training data comes from scripted agents, so the models learn those scripts. Neither model is validated on real people.
- Deep models use leave-users-out CV (8 folds of 5 users) to keep CPU time reasonable; the gradient-boosting baseline uses true
  leave-one-user-out (40 folds).
- Windows ending in step 1 (positioning) are excluded from the rupture model, and the app never raises a risk warning during step 1.
  An earlier version clamped rupture lead-up windows to the run start, which made idle step-1 windows look 88% positive; that
  sampling bug was fixed and the data regenerated.
- The skill estimate in the debrief is computed in the browser and is not part of the server-verified score.
